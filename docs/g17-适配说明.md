# dsh-purge 1.1.71-g17 — DSH Go 1.1.0 适配说明

## 产物
- 源码仓库：<https://github.com/ssacko510-stack/dsh-purge-go>（Go 线；桌面线在 `ssacko510-stack/dsh-purge-fork`）

## 相对 g16 的改动
1. `package.json`：version `1.1.71-g16` → `1.1.71-g17`；description 改为「适配 DSH Go 1.1.0（内置 DSH 0.2.2-rc.1）」；
   `dsh.install.tarball` 指向 `v1.1.71-g17` 的新资产。
2. **补丁表零改动**。85 条补丁、227 个 replacement 一个没动 —— 1.1.0 上没有任何锚点漂移。
   `lib/core.js` 只在 #86 的 g16 锚点旁追加一行 [g17] 说明注释（1.1.0 的 steer 分支与 1.0.16 逐字一致）。
3. `lib/update.js` 注释里的示例版本号改为 `1.1.71-g17`（行为不变：面板内自动更新仍降级成「无更新」）。
4. 文档：README / README.zh-CN / FORK-NOTES / MAINTENANCE / release-notes 全面换到 1.1.0 与 g17；
   `scripts/verify-pack.js` 改成接受 `<unpacked-package-dir> <engine-tree>` 两个参数，不再写死 g16 路径。

## 引擎树怎么来的（可复现）
- 上游 `ccch1mneyyy/dsh-Go` tag `v1.1.0`（`update.json` 里 `version = 1.1.0+11150838`）。
- 它的 `runtime/patches/` 体系：`series`（149 条）+ `pins.json`（每文件 before/after sha256）+ 各 `<name>.diff`。
- 按 pins110 逐文件还原，得到精确引擎树 `eng110`：**105 个文件 / 6.3 MB**，
  逐文件校验「最后一条触及它的 patch 的 after sha256」→ ok 105 / bad 0 / absent 0。
- `eng110` 与 1.0.16 的 `eng` 逐文件比对：**只有 4 个文件不同**，无新增文件。

## 安装
DSH Go → 设置 → 添加插件 → 粘贴资产直链或用短链；或导入本地 tgz 选 `dsh-purge-1.1.71-g17.tgz`；
或用 CLI：`node bin/dsh-purge.js --apply`。装完彻底退出重开 → 会话标题旁 dsh-purge → 清洗页「应用」→ 自动重启一次。
